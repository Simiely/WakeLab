# WakeLab 使用指南

面向「要逐个测试显示器点亮手段」的使用者。界面只有一屏，从上到下依次是：目标显示器 → 独立动作 → 本次结果 → 日志。

## 1. 运行

- 双击 `WakeLab.exe`，无需安装 Python；仅支持 Windows 10/11 x64。
- 首次运行可能看到 SmartScreen：点「更多信息」→「仍要运行」（exe 未签名）。
- 启动只做两件事：枚举支持 DDC/CI 的物理显示器、只读 MCCS 能力串。**启动不会发送任何 DDC 写命令。**

## 2. 勾选目标屏

- 每行显示：显示器序号、型号（能力串 `model(...)`，读不到时用物理描述）、分辨率、`DISPLAYn`、主屏标记。
- 第二行显示能力串声明：`0xD6: 01 04 05 · 0x60: 11 12 0F`（十六进制）。
- 「全选 / 全不选 / 刷新」在右上角；刷新会保留原来勾选的 `DISPLAYn`。
- 能力串读取约 3 秒/台，期间 0xD6=4/5/2 暂不可点；读完后按声明启用或置灰。
- 读回需要目标：除「释放保持」外，未勾选任何屏时动作按钮不可点。

## 3. 执行与计时

点一颗按钮后：

1. 按钮与勾选框全部禁用，避免并发点击。
2. 状态栏显示「正在执行：…（只做这一项，不重试）」。
3. 完成后「本次结果」大字显示：

```
动作 183.4 ms · 含读回 371.2 ms
```

- **动作耗时**：从重新枚举目标开始，到动作本身执行完（不含读回）。多台屏时是整轮动作的总时间。
- **含读回总耗时**：动作 + 每台屏读回 `0xD6 / 0x10 / 0x60` 各一次（约 58 ms/次）。
- 多台屏时日志逐台列出「写 0xD6=1 成功（xx ms）」等，方便分辨是哪台慢。
- 读回只是记录：写成功不代表面板执行，读回值也不参与任何成功/失败判断。

### 三个读回值怎么读

| 读回 | 含义 | 常见值 |
|---|---|---|
| `0xD6` | 电源模式 | 1=开、2=待机、4=软关、5=硬关；「读失败」表示该屏不响应 |
| `0x10` | 亮度 | 0–100；用「0x10 = 读回当前值」可验证亮度通道 |
| `0x60` | 输入源 | 15=DP、17=HDMI1、18=HDMI2（以能力串 `60(...)` 为准） |

0x60 切源往返结束后，`0x60` 应回到动作前的原值（实测两台 Legion R27qe Gen2 都是 15）。

## 4. 各按钮的行为与风险

| 按钮 | 行为 | 风险/恢复 |
|---|---|---|
| 0xD6 = 1 唤醒 | 对每台勾选屏写 `0xD6=1` | 安全，常用恢复点 |
| 0xD6 = 4 软关 | 写 `0xD6=4` | 可能直接黑屏；恢复点 `0xD6=1` |
| 0xD6 = 5 硬关 | 写 `0xD6=5` | 可能直接黑屏；恢复点 `0xD6=1` |
| 0xD6 = 2→1 | 写 2 → 800 ms → 写 1 | 本机能力串未声明 02，按钮置灰 |
| 0x10 = 读回当前值 | 读 0x10 后原值写回 | 安全 |
| 0x10 = 100 | 写 `0x10=100` | 亮度会跳到 100 |
| SC_MONITORPOWER -1 点亮 | 系统广播 | **影响全部显示器** |
| 输出回收 2→800ms→-1 | 先广播关屏，800 ms 后广播点亮 | **影响全部显示器**，会闪黑一次 |
| 0x60 切源往返 | 读原值 → 写 17 → 等待 → 写回原值 | 等待必须填 0（已验证） |
| 保持显示 | `SetThreadExecutionState(0x80000002)` | 仅当前线程有效 |
| 释放保持 | `SetThreadExecutionState(0x80000000)` | 安全 |

### 哪些按钮会黑掉全部显示器

「系统广播」分组的两颗：`SC_MONITORPOWER -1 点亮` 与 `输出回收 2→800ms→-1`。它们通过 `SendMessageTimeoutW(HWND_BROADCAST, …)` 发给所有顶层窗口，**不受勾选影响**。恢复方式：再点一次 `SC_MONITORPOWER -1`，或正常移动鼠标/按键唤醒（本程序自身不做注入）。

### 0x60 切源往返：等待必须填 0

- 这是已实测确认的用法：等待 `0 ms` 即可点亮，动作约 183–188 ms。
- 两台 Legion R27qe Gen2 各测一次，目标 DISPLAY2；含读回约 368–372 ms，读回源值回到 15。
- 等待框只接受 `0–10000` 的整数；填更大值只会让总耗时更长。
- 按钮旁绿色徽标「✓ 已验证 · 0 等待可点亮」即指此结论。

### 为什么 `0xD6 = 2→1` 是灰的

程序按 MCCS 能力串决定可点性。两台 Legion R27qe Gen2 的能力串是 `D6(01 04 05)`，没有声明 `02`（待机），因此按钮显示「（未声明 02）」并置灰，避免对未声明值盲写。若换一台声明 `02` 的显示器，按钮会自动可点；部分屏声明、部分未声明时按钮可点，日志会逐台写「跳过：能力串未声明 0x02」。

## 5. 日志

- 「日志」区记录：启动、刷新、能力串结果、每次动作的 API/目标/逐条结果/读回/总耗时。
- 「复制日志」把全文放进剪贴板，可直接粘贴；「清空」只清显示，不影响程序状态。
- 要对比多次测试，建议每测完一颗按钮就复制一次日志，或在日志里保留完整序列。

## 6. 常见问题

- **能力串读取失败**：该屏 DDC/CI 被关闭、线材只有部分针脚、或 KVM/转接器不透传；0xD6=4/5/2 会保持置灰。
- **动作显示成功但屏没亮**：`SetVCPFeature` 返回成功只代表命令送达；面板可能忽略。换按钮或换线材再测。
- **读回全是「读失败」**：屏进入深睡后 DDC 通道可能掉线，先点 `0xD6=1` 或 `SC_MONITORPOWER -1`。
- **两台同型号分不清**：用行首序号与 `DISPLAY1/DISPLAY2` 区分；必要时在 Windows 显示设置里确认排列。
- **exe 被杀毒误报**：PyInstaller onefile 常见误报，可加信任；源码在仓库可自行打包。

## 7. 离线自检

```
WakeLab.exe --selftest
```

不打开界面、不访问 dxva2、不发送任何 DDC 命令；只检查能力串解析、门槛逻辑、按钮清单与版本号，结果写入同目录 `selftest.txt`（当前 20/20 通过）。
